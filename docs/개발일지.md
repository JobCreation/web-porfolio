## 검증 기록

### 2026-11-26 · 플랫폼 전환
- 지금까지 한 일: 1인용 정적 사이트 → 여러 사용자가 쓰는 플랫폼(서버 함수 + 자료 보관)으로 구조 변경.
- 확인한 것
  - 가입 2명(운영자 1, 일반 1), 로그인·로그아웃, 잘못된 비밀번호 거부
  - 일반 사용자가 `/api/users` 호출 시 403, 로그인 없이 업로드 시 401
  - 개인 admin에서 글 수정 → 저장 → `/r/<주소>` 공개 화면에 반영
  - 서식 5종 모두 다른 모양으로 그려짐 (미리보기에서 즉시 전환)
  - 파일 올리기: 85바이트 PNG 올리기 → 목록 → 내려받기(200) → 형식 거부(.exe) 확인
  - 운영자가 다른 사용자의 이력서를 열어 이름·직함을 고치고 저장 → 그 사용자의 공개 화면에 반영
  - 휴대폰 폭(375px) 가로 넘침 0, 어두운 화면 정상
- 못 한 것 / 알아 둘 것
  - 배포 환경에서는 아직 못 돌려 봤다. Vercel은 파일을 쓸 수 없어 Supabase 키가 없으면 가입이 막히고, 그 경우 화면에 안내가 뜨도록 해 두었다.
  - 비밀번호를 잊으면 본인이 되돌릴 방법이 없다. 지금은 운영자가 재설정해 주어야 한다.
  - 사진·파일은 올린 사람 외에 운영자도 볼 수 있다. 공개 이력서에 넣은 사진은 주소를 아는 사람이면 볼 수 있다.

- Supabase(서울, Free) 프로젝트 `resume-platform`, 표 3개와 공개 보관함 `uploads` 생성
- Vercel Hobby로 저장소 연결, 환경변수 5개 등록, 배포 보호(Vercel Authentication) 해제

- 배포 서버에서 확인: 가입(일반 사용자), 이력서 저장, 공개 이력서 읽기, 사진 업로드(Supabase Storage 공개 주소), 일반 사용자의 운영자 API 접근 403
- 확인에 쓴 계정과 파일은 삭제. 운영자 계정은 사용자가 OWNER_EMAIL 주소로 가입하면 생성됨
- 남은 일: 채팅에 노출된 Supabase secret 키 교체

## 구조 메모

- 화면: `platform/` (들머리·개인 admin·운영자·공개 이력서), 공통 디자인 값은 `assets/css/tokens.css`
- 서버: `api/*.mjs` (Vercel 서버리스 함수와 같은 모양, 바깥 라이브러리 없음)
- 자료: Supabase(배포) 또는 `.data/db.json`(내 PC). `api/_lib/store.mjs` 한 곳에서 갈라진다
- 로그인: 비밀번호는 scrypt 해시, 로그인 상태는 서명한 HttpOnly 쿠키 (`SESSION_SECRET`)
- 예전 1인용 사이트는 `/`(GitHub Pages)와 `/me`(Vercel)에 그대로 남아 있다
